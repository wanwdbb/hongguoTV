# 优化与观看记录写回

## 实现

- 下载入口、原生更新、公开同步工作流统一为 wanwdbb/hongguoTV。同仓库直接发布，禁止公开导出脚本把仓库覆盖到自身。未推送远端或发布版本。
- 基础详情先显示分集；主创和相关推荐后台补齐，失败显示单独重试入口，不抢焦点。
- 首页保留未变化分区的 View 和封面绑定，结构变化仍恢复稳定焦点及滚动位置。
- 提取 PageWork 生命周期控制器和 Screen 类型，保留旧页面请求取消与后台延后应用结果的行为。
- 分段读取以 Long 比较剩余长度，避免超过 2 GiB 时截断。
- 图片解码有效后写入缓存，坏图清除；读取刷新热度，批量清理。清理阈值为 24 MiB/100 文件，批次间最多暂存七个新文件。
- 旧版搜索缓存最多保留 12 个已完成查询，10 分钟过期，每个查询保留最近 300 条。

## 账号观看记录

- 依据本地抓包 schema 实现 POST /reading/bookapi/read_history/update/v，使用当前登录会话；不使用抓包中的 Cookie 或令牌。
- 每五秒本机保存的播放检查点进入独立后台队列，约 15 秒合并上传；暂停时尝试提前发送。失败后保留本机队列重试。
- 上传包含剧集、分集、毫秒播放位置及更新时间，vid_index 转为上游使用的一起始序号。
- 首次登录认领已有游客观看记录；其他账号已经认领的本机记录不会被再次导入。退出登录后新产生的游客记录可由下一次登录认领。
- 待同步记录按账号哈希隔离，不在队列保存登录凭据。首次发送前读取云端记录，跳过时间更新的云端记录。
- 上游已确认响应 code=0 才移出队列；这代表写请求获接受，跨端可见性仍需实际回读验收。
- 旧记录缺少内容类型时，以云端记录或搜索结果精确剧集 ID 匹配补齐；无法确认的类型保持待同步，不猜测类型。未知类型不会阻塞同批已确认类型。
- 每个账号最多保留最近 500 部待同步记录。本机记录删除不会删除云端记录。

## 验证

运行 core 单元测试、Android lint、APK 构建，以及旧版 TypeScript 检查和测试。模拟器安装使用用户指定的 Pets.jks，签名密码仅通过进程环境传入，不落盘。
实际测试结果见交付回复；构建和模拟器测试不能替代实体电视性能与账号跨端验证。

## 2026-10-25 继续优化

- 账号历史读取固定使用调用时捕获的会话，请求间及返回前检查换号；换号后停止本轮，避免合并不同账号的数据。
- 每轮重试前重新读取云端较新进度，避免首次合并后长时间重试继续沿用旧快照。检查与上传不是服务端事务，不能保证消除其他设备恰好同时写入的竞争。
- 已知类型记录优先上传；单条旧记录解析失败或字段不合法时保留并跳过，不阻断同批正常记录。网络或服务端批次失败仍保留整批重试。
- 更新项目现状，明确历史 RN 文档与当前原生客户端，保留历史验收证据。

低配实体电视的长期内存趋势、弱网连续切换与跨端同时写入仍需真实设备环境测量；未将模拟器播放等同于这些验收。
## 2026-10-25 补传限流

每轮最多选取 20 条已确认有效记录和 3 条需要补查的旧记录；正常记录先处理。失败旧记录在进程内冷却 5 分钟，优先尝试尚未处理或最早尝试的记录。冷却状态不包含凭据，进程重启后重新开始；待上传内容仍持久化。冷却期间无可处理记录时不读取云端；其余批次间隔约 15 秒继续，不会一次扫描 500 部详情。

## 播放链接与账号同步

当前播放器链接和账号登录是独立授权。CDN 地址中的签名通常只允许读取媒体，不等价于观看记录接口的 Cookie/token；不能凭此声称账号已登录。准确同步至少需要有效账号会话、剧集 ID、分集 ID和播放位置。

当前版本没有新增携带 Cookie/token 的外部播放入口。可后续接入两种流程：手机发剧集/分集链接，电视沿用自身登录账号；或短时一次性授权码经受信任的服务交换会话。后者需要明确授权码签发方、有效期、一次性消费和账号确认机制，现有纯 APK 不会自行提供这些服务。长期凭据不应拼入可分享的 URL。
## 独立续播进度接口（2026-10-25 修复）

本地抓包同时存在 read_history 与 read_progress 两套接口。仅 read_history 回读一致不能证明其他客户端续播一致。

- POST /reading/bookapi/read_progress/upload/v：JSON books 数组。book_id、item_id 为字符串；current_play_time 与 read_timestamp_ms 以毫秒传入。按抓包 vid_index=0，实际分集以 item_id 指定；不得将历史接口的一起始 vid_index 直接套用。
- GET /reading/bookapi/read_progress/list/v：limit=0、book_types=2,3,4、last_min_read_timestamp_ms_list 为空。video_data 包含 series_id、vid、vid_index、current_play_time、last_watch_time。
- 后台检查点同时写历史和续播接口；两者均明确返回 code=0 才移除待同步记录。历史成功而续播失败时必须保留重试。
- 重试合并同时检查两套云端时间；相等历史记录而续播缺失时继续补传，避免误判已完成。其他客户端实际续播仍需回读和界面验证。

排查当时正式版本地与历史接口均为第 13 集、126576ms，待同步 0；此前缺少独立续播进度写入，不能据此将历史上传当作完整跨端同步。
## 2026-10-25 云端回填与续播前校验

修复云端已更新而本地仍留旧位置、点击后又以新时间覆盖云端的问题。

- 登录后的启动/回到前台，以及读取账号历史时，合并观看历史与独立续播接口，按更新时间回填本地索引并后台持久化。
- 回填保留服务端时间；同位置但较新的云端时间也会导入，不会因为位置相同而保留旧时间。导入本身不进入上传队列。
- 点击续播、打开详情/推荐剧和后台返回播放器时，重新核对当前账号云端记录再选择位置；账号核对或请求失败时不自动使用旧位置开播。
- 本机实际观看时间较新时仍保留本机记录；云端较新的重新观看可回到较早集数，不以最大集数合并。
- 已在前台播放的剧不会被后台拉取强行跳集；明确选集和重新观看仍代表用户主动操作。
- 尚未提供“登录状态下忽略云端直接离线续播”的入口；云端核对失败需要联网重试。这避免静默沿用过期位置，但增加了登录后开播前的网络依赖。
