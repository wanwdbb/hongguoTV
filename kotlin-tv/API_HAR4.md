# 红果接口4.har 核对与修复

日期：2026-10-28。输入为本机红果接口4.har，共 745 条记录；本报告不包含请求凭据、设备标识、媒体密钥或临时播放地址。

## 播放变化

抓包包含 11 次正式 player 请求与 7 次 preload 请求，共提取 50 份分集模型。正式路径为 `/novel/player/multi_video_model/player/v1`，请求包含 `dr_scene: player` 与 `disable_video_relate_book: false`，客户端版本 7.3.9.32。响应 `data` 按请求分集 ID 索引，`video_model` 为 JSON 字符串；模型状态观察为 10，不能把它误判为 HTTP/API 错误码。

新模型 `video_list` 为数组，编码/分辨率位于 `video_meta`，加密描述位于 `encrypt_info`。旧客户端固定走 preload，再无条件调用 fallback_api，只识别旧版对象形式的 video_list，导致请求链变长，也缺少新结构兼容。

修复后优先使用正式 player 路径，按抓包使用 gzip 请求体和匹配的版本标识；签名摘要与发送内容都采用压缩后的字节。player 请求网络失败、空响应或接口报错时，保留已有 preload 请求作为兼容回退，不把抓包中的某一次成功当作所有设备都能使用 player 的证明。

取得模型后优先解析直返资源，仅在缺少可用资源时解析旧式 fallback_api。支持数组/对象资源列表及新旧字段布局，保留原有媒体读取和解密实现。过滤 ByteVC2，避免出现只有声音无画面；抓包有部分资源仅 1080P 是电视可用编码，此时沿用兼容资源提示。严格匹配请求的分集 ID，批量返回缺少目标时不取第一条冒充当前集。加密信息缺失或格式未知时明确失败。空响应返回 IOException，可进入现有自动恢复流程。

这是已确认的协议兼容缺口；是否为用户当前每次播放失败的唯一原因，仍以实际联网/设备验证为准。

## api4.1 设备身份失效修复（2026-10-28）

用户反馈 api4 在模拟器和电视中均失败。模拟器复现为出帧前 player 与 preload 均返回空内容，并非解码器错误。应用内对照使用同一个失败分集：原持久化设备身份，登录/匿名均 empty_response；重新调用正常设备注册接口，仅在内存应用新身份，登录/匿名均 media_ok，完成 RemoteVideo.prepare 和 8192 字节读取。保留模拟器原时钟重复后仍成功；约 24 分钟时钟偏差不是此故障的必要原因，不加入未经必要性验证的时钟改写。

api4.1 保留 player/preload 兼容链。当链路最终返回空内容时，正常注册新设备身份，重新签名并仅重试一次。每个 repository 的注册尝试间隔至少 5 分钟，并对设备更新加锁；若期间其它请求已更新身份，则复用其结果。注册失败保留旧身份，持续空响应不会无限注册。常规网络异常、模型不兼容不会触发这条恢复。成功身份保存到原设备偏好设置，账号会话、观看历史及最远进度规则保持不变。移除设备注册日志中的具体 install_id。

新增回归覆盖：空响应恢复与重新签名、保存回调和登录保留、连续播放重试的注册上限、注册失败不覆盖旧身份、网络故障不更新身份。诊断 instrumentation 只用于模拟器，不加入正式包。正式包版本名 0.9.18-api4.1、versionCode 10019，使用原发布签名，允许保留数据覆盖安装。

后续签名包出帧和冷启动结果以 api4.1-runtime-evidence.txt 为准。旧 api4 验收只是当时单次成功，不能证明持久化设备身份永远有效。真实长虹电视需安装本修复包后再次核验。
